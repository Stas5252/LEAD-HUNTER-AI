## 1. Применение сетевых настроек среды

В настройках облачной среды сохранён draft с адресами:

- api.telegram.org
- shprotoness-ai.jq9gfk.workers.dev
- overpass-api.de
- stanislavweb.ru
- www.stanislavweb.ru
- graph.threads.com
- graph.threads.net

Владелец открывает настройки этой среды, проверяет и сохраняет изменения,
затем публикует конфигурацию. Сохранение draft инструментом не применяет сеть
к текущему процессу. Нельзя обходить session proxy или отключать TLS-проверку.
После фактического применения нужно заново проверить runtime policy и живой запрос.
Список не даёт безопасный произвольный HTML/RSS transport через CONNECT proxy:
для него нужен поддерживаемый transport на постоянном сервере.

После подтверждения доступности Overpass оператор запускает:

```bash
.venv/bin/python scripts/sources.py configure maps config/examples/maps-saratov.json --enable
.venv/bin/python scripts/sources.py run maps
.venv/bin/python scripts/sources.py status
```

Результат проверяется по job и настоящим карточкам, без DEMO-подстановки.
Пилот — один небольшой район и одна ниша. Это ещё не автоматический обход всей
России: для страны нужны очереди областей/ниш и соблюдение лимитов провайдера.

## 2. Постоянный сервер

Сейчас бот работает в текущей временной облачной сессии. Root disk 32GB заполнен;
восстановление в новую БД и создание новых контейнеров заблокированы. Существующие
службы работают, но это не гарантия бесперебойности. Безопасная очистка только
кэшей/неиспользуемого образа задачи уже проверялась и не решила проблему.
Системные данные и volumes не удалять. Нужен ресурс со свободным диском или помощь
службы облачной среды. Текущие venv/media/backups в /tmp не считать постоянными.

Подготовлен перенос на Railway Trial: см. RAILWAY_DEPLOY.md. У владельца ещё нет
предоставленного доступа к такому проекту. Trial ограничен кредитом и сроком;
бесплатная постоянная работа полного стека не подтверждена. Cloudflare Workers
не запускает текущий Docker/n8n/PostgreSQL/FFmpeg стек; Tunnel не заменяет сервер.
GitHub Pages сайта не поддерживает запуск текущего серверного стека.

## 3. Доступы к соцсетям и сайту

Скриншоты аккаунтов и публичные ссылки не дают OAuth-доступа. Сначала нужен
подключённый Postiz instance с собственными integrations, затем проверка
POSTIZ_API_URL / POSTIZ_API_KEY через защищённые настройки. Для Threads Search —
THREADS_ACCESS_TOKEN и подтверждённые разрешения Meta; ключи не размещать в JSON
источников. Установить приложения в аккаунты и пройти OAuth должен владелец.

Для Telegram нельзя искать все чаты через Bot API. Нужны доступные выбранные чаты,
бот с правами чтения и согласованная allowlist. По ссылке/ID сначала проверить
getChat/getChatMember; только после этого включать мониторинг. Новую личную
переписку и рассылки клиентам автоматически не запускать.

Для статического GitHub Pages реализован переход в Telegram-бот: см. WEBSITE_INTAKE.md.
Отдельный серверный HTTP webhook необязателен; если он нужен, INGEST_TOKEN остаётся
на сервере и никогда не попадает в браузерный JavaScript.

## 4. Критерии полного запуска

1. Постоянный сервер: автозапуск после перезагрузки, свободный диск, backup и
   успешный restore в отдельную БД. Последний restore сейчас заблокирован ENOSPC.
2. Каждый включённый источник: хотя бы один живой результат с URL/доказательством,
   дедупликация и доставка владельцу; недоступные источники явно обозначены.
3. ИИ: реальный /models и inference на выбранной модели внутри согласованного
   лимита. Сейчас бюджет 0 и вызовы 0; ключ сам по себе не подтверждает бесплатную квоту.
4. Собственные соцсети: OAuth, проверенная integration, предварительный просмотр
   и отдельное одобрение первой реальной публикации.
5. Форма: настоящая заявка с согласия владельца формы/посетителя → CRM → Telegram.

Сейчас эти критерии выполнены частично. Доказательства локальных проверок и живой
Telegram-доставки приведены в STATUS.md и VERIFICATION.md. Код сохранён в GitHub; ссылки актуального сайта подключены в gh-pages.
Постоянное серверное развёртывание бота ещё не выполнено.
