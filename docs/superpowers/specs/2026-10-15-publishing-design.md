# Подсистема B2: Threads, Instagram и собственный контент

Статус: одобрено пользователем 2026-10-15; выполнение в текущей сессии. Контекст: [общая спецификация](2026-10-15-completion-design.md).

## Границы

Собственные аккаунты владельца, полезный контент и входящие диалоги. Postiz управляет
публикациями, а официальный Threads API — поиском и доступными социальными методами.
Postiz не считается поиском чужих постов. Никакого массового outreach.

## Подключения

До реализации HTTP-вызовов исследовать текущие официальные API/DTO и зафиксировать
версию, scopes, ограничения и payload. Не выдумывать endpoints. Предпочтение —
официальному Postiz API, если его проверенная версия поддерживает нужные операции.
Self-hosted Postiz — отдельный профиль/инструкция после проверки CPU/RAM, зависимостей
и лицензии. Если не подходит, реализовать необходимую официальную публикацию напрямую.
Внешняя Postiz-инсталляция подключается base URL и scoped API key.

Threads Search требует Meta App/OAuth и реально предоставленного разрешения поиска;
состояния token missing/expired, permission denied и review pending различаются.
Instagram — собственный Professional account с поддерживаемым способом OAuth.
Для каждого аккаунта хранится доступный набор операций, а не общий флаг «подключено».
OAuth state/redirect и refresh защищаются, токены хранятся в credentials/защищённых
настройках, не в экспортах workflow и таблицах с открытым доступом.

## Поиск и ответы

Threads queries задаются по-русски, с фильтрами времени/языка и cursors. Записи
проходят общее распознавание намерений и дедупликацию по post ID/permalink. Без
доступа поддерживается ручной импорт публичной ссылки, честно помеченный как ручной.
Ответы и упоминания на собственном аккаунте при доступных permissions создают
входящие события и персональные черновики, не массовые автоответы.

## Контент и очередь

content_items содержат тему/нишу, текст, тип поста/карусели/Reels, media IDs,
целевой собственный аккаунт, расписание/timezone, версию, состояние и attribution.
Общие состояния DRAFT → REVIEW → APPROVED → SCHEDULED → PUBLISHING → PUBLISHED
с FAILED/UNCERTAIN/CANCELLED. Неоднозначный результат публикации сначала сверяется
с provider ID/статусом, а не повторяется вслепую.

Каждая публикация имеет approval на точную версию текста+медиа+канал. Изменение
отзывает approval. Сразу перед отправкой повторно проверяются STOP, лимит/день,
права на медиа и владельца аккаунта. AUTOPUBLISH включается только отдельным
действием владельца после успешного live e2e; AUTO_OUTREACH остаётся false.

Тексты на русском, без вымышленных выполненных работ и обещаний дохода. Без
OpenAI доступны редактируемые шаблоны; AI-генерация использует общий бюджет/кэш.
Основная бизнес-метрика — атрибутированные входящие обращения и сделки; просмотры
и лайки показываются отдельно и только по данным собственных аккаунтов.

## Telegram и приёмка

/threads и /instagram дают доступы, поиск/черновики, очереди и ошибки. Кнопки
предпросмотра, правки, конкретного одобрения, отмены и STOP доступны только владельцу.
Проверки: schema/payload текущей версии, pagination, OAuth state/expiry, permissions,
out-of-order provider callbacks, одновременные workers, approval revocation,
дневной лимит и UNCERTAIN. HTTP mocks запускаются через n8n. Живой поиск и
контрольная публикация проверяются отдельно после доступов и явного разрешения.
