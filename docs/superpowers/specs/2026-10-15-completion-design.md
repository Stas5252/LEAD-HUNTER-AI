# LEAD HUNTER AI — завершение проекта

Дата: 15 октября 2026 года. Статус: спецификация на согласование.

## Задача и критерий результата

Пользователь поручил завершить весь исходный промпт и сообщать, какие доступы нужны.
Основа этапа A сохраняется: n8n, PostgreSQL, Telegram-пульт и небольшие адаптеры.
Результат — реальные independently enabled сценарии всех девяти направлений,
официальные социальные интеграции и видео-конвейер с подтверждаемыми правами.
Тестовая фикстура, зарегистрированный endpoint или добавленный ENV не означают
работу настоящего провайдера. Статусы реализации и живой проверки учитываются отдельно.

Объём разделён на три самостоятельные подсистемы с отдельной приёмкой:

1. [Источники и CRM](2026-10-15-sources-design.md): живые источники, аудит, формы,
   нишевые предложения, мониторинг и учёт результата.
2. [Соцсети и публикации](2026-10-15-publishing-design.md): Threads Search,
   контент-план, Postiz/официальные API, ответы, расписание, метрики.
3. [Медиа](2026-10-15-media-design.md): разрешённые исходники, сценарии, монтаж,
   карусели, preview, очередь публикации.

Общий план реализации составляется по этим трём документам. Разработка выполняется
в текущей сессии и существующем checkout, без создания дополнительного worktree.
Покупки, подключение личных аккаунтов, реальные коммерческие сообщения и публичные
публикации требуют конкретного разрешения владельца; согласование кода его не заменяет.

## Архитектурные варианты

- Выбран: расширить существующий n8n/PostgreSQL. Стандартные ноды обеспечивают
  расписания, credentials и маршрутизацию. Небольшой worker/CLI занимается только
  адаптацией данных, защищённым HTTP-аудитом и локальными медиа-задачами.
- Отдельный универсальный backend/новая CRM отклонены: дублируют готовые компоненты.
- Одновременное включение тяжёлых браузеров и всех вспомогательных продуктов
  отклонено: Postiz и медиа включаются отдельно после оценки ресурсов.

## Общие обязательства

- Девять acquisition-сценариев имеют отдельные workflow, настройки, примеры и логи.
  Отсутствующий доступ отражается в NEEDS_ACCESS/NEEDS_KEY/NEEDS_APP_REVIEW, а не
  фиктивным результатом или молчаливым пропуском.
- Источники, audit, content и media проходят через общий STOP, дедупликацию,
  ограниченные очереди, bounded retries, идемпотентные внешние действия и audit log.
- Одобрение связывается с версией текста/медиа, каналом и конкретным действием.
  Изменение любого из них отзывает одобрение. DNC блокирует коммерческие действия.
- AUTOPUBLISH=false, AUTO_OUTREACH=false, VIDEO_GENERATION_PAID=false сохраняются.
  Публичные посты первоначально требуют подтверждения. Автоответы чужим людям и
  коммерческие DM по умолчанию не отправляются.
- Моки не обращаются в реальные платные API. Проверки живых аккаунтов запускаются
  отдельно и только с согласованными тестовыми действиями.
- Миграции дополняют существующие таблицы и сохраняют все данные этапа A.
- n8n workflow и credentials пользователя экспортируются/резервируются до
  автоматического перезаписывания стабильных ID при обновлении.
- Для Docker соблюдаются действующий session proxy и CA trust. Доступ к запрещённым
  доменам не обходится. Установка сохраняет TLS и checksum verification.

## Входные данные от владельца

Секреты только через защищённые настройки или игнорируемый .env: Telegram token,
admin user ID, OpenAI API key, при необходимости ключ поискового провайдера,
Postiz API key и Meta OAuth credentials. Не запрашивать все ключи заранее без
реализованного/выбранного адаптера и проверки текущих bindings.

Несекретные данные: сайт и портфолио, услуги/диапазоны цен, приоритетные ниши/города,
бюджет сервера/API, доступные группы/каналы, собственные соцаккаунты, источник прав
на медиа. Пока их нет, используются обозначенные примеры и стандартные настройки;
отсутствие предпочтений не останавливает независимую разработку.

## Итоговая приёмка

1. Установка на чистом DEMO-инстансе, миграции и повторное обновление не теряют данные.
2. Каждый из девяти workflow выполняет свою бизнес-функцию, а не возвращает только
   текстовый статус. Разрешённые импортеры считаются импортерами, не live-поиском.
3. Хотя бы один настоящий источник проходит путь до карточки владельца и содержит
   проверяемое доказательство, дату и источник; DEMO не смешивается с real.
4. Аудит подтверждает замечания, не придумывает дефекты и не открывает private networks.
5. Разрешённые Meta/Postiz операции проверены с собственными аккаунтами; при
   отсутствии разрешений соответствующие модули остаются явно непроверенными.
6. Разрешённый клип проходит FFmpeg, preview и подтверждённую очередь; fixture-медиа
   остаётся обозначенным тестовым материалом.
7. Отдельно проверены STOP, DNC, устаревшее одобрение, потерянный ответ провайдера,
   перезапуск, бюджет, бэкап и восстановление.
8. Подготовлены постоянный запуск, обновление, HTTPS/OAuth при необходимости,
   мониторинг и отчёт расходов с явными допущениями. Без VPS/аккаунтов не заявляется 24/7.
