# Подсистема B1: источники, аудит и результат

Статус: одобрено пользователем 2026-10-15; выполнение в текущей сессии. Контекст: [общая спецификация](2026-10-15-completion-design.md).

## Цель

Получать реальные, проверяемые сигналы потребности и согласованные входящие заявки,
проводить честную квалификацию и связывать действия с результатами CRM.

## Девять сценариев

| Сценарий | Рабочая реализация |
|---|---|
| 1. Карты | Бюджетный первый провайдер — OpenStreetMap/Overpass по явно заданному городу/bbox и нишевым тегам. Запросы ограничены по объёму/времени, с кэшем, атрибуцией и соблюдением правил public endpoint. Отсутствие website tag означает UNKNOWN. Адаптеры Яндекс/2ГИС добавляются только после проверки реально доступного API/условий. |
| 2. Новые бизнесы | Специализированный importer разрешённой CSV/JSON/RSS-выгрузки: регистрационный ID, дата регистрации, город, источник. Регистрация не считается прямым запросом. Нужен отдельно предоставленный законный источник для автоматического получения. |
| 3. Telegram | Мониторинг только заданных владельцем чатов/каналов, куда боту предоставлен необходимый доступ. Обрабатываются сообщения и правки, сохраняются permalink/date. Прямые запросы отделяются от предложений исполнителей, вакансий и рекламы. |
| 4. Аудит и КП | Ограниченный HTTP/HTML-аудит разрешённых сайтов: ответ сервера, HTTPS, metadata, viewport, формы/контакты. Каждое замечание связано с наблюдением. Не обещать инструментальную оценку адаптивности/скорости без соответствующего измерения. Затем персональный черновик КП. |
| 5. Нишевые решения | Каталог реальных демонстрационных пакетов и owner portfolio; подбор к нише/потребности. Пока работ нет — честные шаблоны предложений без вымышленных кейсов/отзывов. |
| 6. Субподряд | Поиск через проверенный официальный search provider при ключе либо разрешённые RSS/Atom и импорт публичных запросов. Отличать подряд от найма в штат. Не выдавать ручной importer за автоматическую поисковую систему. |
| 7. Свой сайт | Отдельный подписанный webhook формы: явное согласие, минимальные контактные данные, UTM, source, idempotency key. Бот показывает заявку и напоминания; скрытой идентификации посетителей нет. |
| 8. Партнёры | Разрешённый поиск/RSS/importer публичных партнёрских сигналов с отдельной классификацией и предложением сотрудничества. Черновик до ручного одобрения. |
| 9. Контент | Связь с подсистемой публикаций: план → черновик → одобрение → пост → UTM/входящая заявка → CRM. |

## Компоненты и потоки

Каждый collector имеет отдельный workflow и конфигурацию. Общие таблицы содержат
sources, connector_jobs, runs/errors, cursors, разрешённые chat IDs/domains и
provider capabilities. Работающий адаптер возвращает нормализуемые записи с
source_type, provider ID, permalink, publication/observation time и доказательством.
Запуск и расписание принадлежат n8n, общий intake использует существующий pipeline.

Произвольные JSON/CSV/RSS из Интернета не получают credentials владельца. Внешний
контент — данные, не инструкции. Объём, TTL, per-host rate limit и число записей
ограничиваются. Не обходить captcha, запреты платформы и недоступные источники.

Telegram ingress разводит admin/private commands и разрешённые monitoring updates
до игнорирования посторонних чатов. Update ID фиксируется атомарно с постановкой
лида в очередь; polling offset продвигается только после durable enqueue.
Один update не вызывает повторный импорт, правка поста обновляет старый лид.

## HTTP-аудит

Использовать зрелый HTTP/HTML parser, небольшой защитный адаптер и allowlist
одобренных целей. Запрещены userinfo, нестандартные схемы, localhost/private/
link-local/metadata адреса, перенаправления на них, бесконтрольные DNS-переходы,
неограниченная загрузка и передача provider credentials проверяемому сайту.
TLS проверяется. Когда используемый proxy/transport не обеспечивает необходимую
защиту, аудит завершается с явным статусом, а не выполняется небезопасным обходом.
Тяжёлый браузер необязателен и выключен в экономном режиме.

## CRM и Telegram

Дополнить управление источниками и заданиями: включение/выключение, запуск с
нишой/городом, последний результат/ошибка, evidence, reminders и переходы сделки
CONTACTED/REPLIED/NEGOTIATION/WON/LOST. Не ставить CONTACTED от одного одобрения.
Результаты, расходы и attribution видны в /stats. Подключение формы и исходников
выполняется через подписанные/аутентифицированные маршруты.

## Проверки

Повторные imports/updates/cursors, изменённые контакты, DNC, old approvals, malicious
HTML/CSV, пустые feeds, rate limit, private URL/redirect/DNS, подмена подписи формы,
отсутствие согласия, STOP и восстановление после падения. В настоящем n8n прогоняются
все collector/importer ветки на контролируемых данных. Live OSM/RSS выполняются
только при доступной сети; их результаты проверяются отдельно от mocks.
