# Заявки со статического сайта через Telegram

Сайт найден в https://github.com/Stas5252/Stanislav; CNAME подтверждает
stanislavweb.ru. Это статический GitHub Pages, серверной формы нет.

Два основных CTA и три кнопки тарифов ведут в @LeadMagnetic67_bot с параметрами
web_general / web_landing / web_multi / web_expert. В браузере нет токенов.

Посетитель запускает бота, явно соглашается на передачу задачи и контакта
Станиславу, описывает задачу и выбирает доступный контакт. Если Telegram username
есть, достаточно кнопки «Ответить мне в Telegram». Если его нет, нужны email,
телефон либо собственный контакт через request_contact. Чужой shared contact
отклоняется. /cancel отменяет незавершённую заявку, сессия ограничена 24 часами.

Завершение создаёт один import_requests с source=telegram_inbound,
source_type=website_forms и зафиксированным согласием. Общая очередь выполняет
нормализацию, дедупликацию, CRM и доставку карточки владельцу. Входящие заявки
обходят LLM: модель не тратит квоту и не может подавить настоящую заявку.
Параметр перехода сохраняется как entrypoint; происхождение клика с сайта
не считается доказанным (origin_verified=false), потому что deep link можно
скопировать. Данные задачи не изменяются и не дополняются выдуманной цитатой.

Ответы посетителю имеют отдельный payload visitor_reply и привязаны к его
private chat ID на сервере. Команды владельца остаются owner-only. STOP блокирует
новые сессии и visitor replies; максимум 5 завершённых заявок на посетителя в сутки.
Повторный Telegram update не создаёт повторную заявку или ответ.
Владелец в своём боте получает административную панель, а не сценарий посетителя.

HTTP-приём подписанной формы остаётся отдельной опцией и не включается этим
сценарием. Доступов к хостингу сайта для статических ссылок не требуется.

Проверено: 35 Node tests; 9 DB tests с ROLLBACK; 5 шагов через настоящий защищённый
n8n webhook с временно остановленным transport и удалением тестовых записей до
его возобновления. Внешние тестовые сообщения посетителям не отправлялись.
В интеграционном тесте подтверждены адресат, keyboard, запрет /stop посетителю,
неизменный Telegram offset и отмена без создания лида. Первичная проверка порядка
сообщений была исправлена добавлением ORDER BY id в диагностический запрос;
повторный сценарий прошёл. Полный старый Python suite не запускался на рабочем
аккаунте; restore acceptance всё ещё ограничен ENOSPC среды.

Долговременная доступность требует постоянного сервера для polling/n8n/PostgreSQL;
GitHub Pages обслуживает только сайт. Текущий bot runtime — временная облачная сессия.
