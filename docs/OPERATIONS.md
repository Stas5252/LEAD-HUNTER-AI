# Эксплуатация

## Запуск и обновление

Все команды выполняются из корня проекта. Фиксированные версии: n8n 2.43.6,
PostgreSQL 17.11-alpine. Не подменяйте их `latest`. Перед обновлением сделайте
backup, проверьте release notes и миграции на DEMO-копии. `setup.py` сохраняет
существующий `.env`; его значения не обновляются автоматически из нового примера.

```bash
docker compose up -d --wait
python3 scripts/migrate.py
python3 scripts/connect.py
python3 scripts/import-workflows.py --activate-local
docker compose ps
```

В этой облачной среде checkout уже изолирован; дополнительный worktree не нужен.
После восстановления snapshot контейнеры и Telegram transport нужно запускать снова.
Перезапуск только своих сервисов: `docker compose restart`. Остановка:
`docker compose stop`. `docker compose down` сохраняет именованные тома;
`down -v` удаляет данные — не используйте его для обычной остановки.

Импортер меняет только workflow с ID `lh-lead-import`, `lh-telegram`,
`lh-transport`, `lh-openai-score` и их именованные credentials. До повторного импорта
сохраните собственные изменения через экспорт n8n или backup.

## Сеть

Для Docker-установки нужны `auth.docker.io`, `registry-1.docker.io` и адреса CDN,
которые Docker возвращает при pull. В текущей среде они уже входят в preset
package_managers. Для реальной работы нужны:

- `api.telegram.org` — Bot API;
- `api.openai.com` — только при явно включённом платном AI;
- `n8n.io`, `docs.n8n.io` — документация и исходный шаблон, не runtime DEMO;
- `raw.githubusercontent.com`, `github.com`, `registry.npmjs.org` — исследование
  официальных исходников/версий, доступны в текущем preset.

Разрешение домена и наличие ключа — разные требования. После изменения сетевых
настроек повторите конкретную проверку. Не отключайте TLS/checksum verification.
Прокси-ключи облачной среды могут требовать платформенного HTTPS-прокси; работу
таких ключей внутри Docker нужно проверять отдельно, не принимать placeholder
за настоящий raw token. В этом запуске внешние API не подключались.

## HTTPS webhook вместо polling

Для начала удобнее polling: домен и публичный порт не нужны. Для webhook:

1. Настройте собственный домен и reverse proxy с действительным TLS-сертификатом.
   Разрешите только POST `/webhook/lh-telegram` к локальному n8n; редактор n8n,
   `/webhook/lh-transport` и PostgreSQL в Интернет не открывайте.
2. Передавайте заголовок `X-Telegram-Bot-Api-Secret-Token` без изменения.
   Он проверяется Header Auth credential в n8n; значение берётся из локального
   `TELEGRAM_WEBHOOK_SECRET`, не из текста сообщения.
3. Укажите собственный HTTPS origin в `WEBHOOK_URL`, перезапустите n8n.
4. После подключения бота явно зарегистрируйте webhook:

   ```bash
   python3 scripts/register_webhook.py --url https://bot.example.ru/webhook/lh-telegram --apply
   python3 scripts/telegram_transport.py --webhook
   ```

5. `--webhook` запускает только доставку очереди; getUpdates одновременно не работает.
   Скрипт регистрации не заменяет чужой существующий webhook без отдельного
   `--replace-existing`. Реальная регистрация в этой среде не выполнялась.

Если нужен внешний доступ к самому редактору, обеспечьте HTTPS, отдельную
аутентификацию, secure cookies и корректные proxy settings n8n по официальной
документации. Текущий Compose предназначен для локального редактора/SSH-туннеля.

## Backup и проверка восстановления

```bash
python3 scripts/backup.py
python3 scripts/restore.py --backup backups/ИМЯ_КОПИИ/lead_hunter.sql --database lh_restore_check
```

Backup создаёт дампы прикладной БД и метаданных n8n. Папка игнорируется Git,
файлы приватные, но скрипт не шифрует носитель. Храните копии отдельно в защищённом
хранилище. **Сохраните `.env`/`N8N_ENCRYPTION_KEY` отдельно**: без исходного ключа
зашифрованные credentials n8n не восстановятся. Команды не выводят значения ключей.

`restore.py` принимает только новое имя `lh_restore_*`, отказывается от существующей
базы и не заменяет рабочие данные. Проверка состава восстановленной БД выполняется
интеграционным тестом. Это безопасная проверка резервной копии; переключение
рабочего сервиса на восстановленную базу — отдельная операция администратора.
Для полной аварийной миграции также сохраните n8n volume, исходную версию образа,
дамп n8n и конфигурацию, затем следуйте официальной инструкции n8n backup/restore.

## Остановка, ошибки и повторная обработка

- `/stop` сохраняется в PostgreSQL, переживает перезапуск и блокирует новые
  сборы/LLM-вызовы/уведомления о лидах. Управляющие ответы владельцу продолжаются.
  Уже принятый внешним сервисом запрос нельзя гарантированно отменить.
- Доставка: PENDING → SENDING → SENT, FAILED или UNCERTAIN. После 429 разрешены
  до трёх попыток с задержкой. Неоднозначная сеть/5xx и прерванная доставка не
  возвращаются в очередь автоматически. Перед ручным повтором проверьте Telegram.
- При изменении черновика старое одобрение отзывается. DNC не снимается импортом.
- Ошибочный импорт не удаляет исходный файл; запись import_requests и приватный
  `.local/run-lh-lead-import.log` позволяют найти причину. Повторный разрешённый
  импорт того же JSON/CSV безопасен для дедупликации; он не снимает DNC и не
  уведомляет повторно о ранее сохранённом лиде. Не создавайте параллельные CLI
  исполнения: отдельный task broker использует порт 5680.
- Журналы контейнеров ограничены 3×10 MB. Успешные n8n executions не хранят
  полные данные, ошибки хранятся до 7 дней. Логи/SQL/дампы могут содержать контакты:
  не публикуйте их. Отладку нельзя вести через `env`, tracing или печать credentials.

## Ориентиры ресурсов

| Сервис | Наблюдалось RAM в idle на amd64 | Планируемый запас | CPU/диск/архитектура |
|---|---:|---:|---|
| n8n | ~370 MiB | 512 MiB–1.5 GiB | Зависит от объёма Code/HTTP; образ и данные занимают несколько GiB; amd64/arm64 опубликованы |
| PostgreSQL | ~40 MiB | 256–512 MiB+ | Нужен дисковый запас для БД, WAL и backups; amd64/arm64 опубликованы |
| Telegram transport | Не запускался с живым токеном | ~30–80 MiB как ориентир, не измерение | Один Python-процесс; лёгкий HTTP, без браузера |
| Postiz/NocoDB/Crawl4AI | Не установлены | Требует отдельного измерения | Следующий этап, не заявлены помещающимися в бесплатный VPS |
| FFmpeg/Video Factory | FFmpeg установлен, фабрика не собрана | Монтаж на ПК или по задаче | Не включён в серверный MVP |

На VPS начните с двух основных сервисов и transport; монтаж оставьте на ПК.
Наличие бесплатной Oracle ARM VM и её квота зависят от аккаунта/региона. На ARM
проверьте сами workflow и вспомогательные зависимости, а не только image manifest.
